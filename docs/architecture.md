# Architecture and decisions

## Processes and responsibilities

`ui/` is a searchable UIKit browser and JSON detail UI. `controller/` owns sessions, request correlation, persistent per-bundle state, bounded history and export. `shared/` owns versioned framed JSON transport and encoding interpretation. `agent/` owns target-side pairing/lifecycle and serialized command dispatch. `runtime/` uses official dyld/Objective-C C APIs. `hook/` owns typed trampolines/original IMPs and bounded call logs. `static/` adapts independent bounded C Mach-O parser in `core/`.

Normal ElleKit/UIKit injection loads Agent. Constructor excludes non-app processes, Apple bundles and Controller. No scanning occurs before explicit activation or a query in a previously authorized launch-patch session. Hook engine allocation occurs only for explicit activation or previously authorized launch restoration. Scene windows are preferred for presentation; App Delegate window is the fallback. A small gesture is installed on foreground notification for local opt-in pairing; TestTarget invokes the same entry point explicitly. Controller must authenticate with the user-transferred session token before it can issue commands. Token is never persisted or exported. PID/bundle identity is claimed by the token-bearing local peer, not kernel-attested; it is diagnostic, not a security boundary against a hostile jailbroken/root process.

Agent's private serial queue handles requests and scanning; main queue handles only pairing UI. dyld add/remove callbacks increment an atomic generation. Scanner rebuilds image cache/class cache after a new-image callback; class lists are paginated at 200. Method data is requested on drill-down. Dynamically registered image-less classes are enumerated freshly through objc_copyClassList under a virtual Runtime Generated group. Image removal invalidates caches; records are point-in-time snapshots, not an atomic transaction across independently changing dyld/runtime state.

## IPC lifecycle

Controller binds IPv4 loopback port 49371 (unique application protocol namespace `jp.league.runtimeatlas`). Agent connects only after local token entry. Hello contains a fresh nonce and HMAC-SHA256 of the identity/nonce; Controller returns a fresh nonce and server proof, Agent verifies it and sends a client proof, then Controller exposes the session. Purpose-separated proofs bind both nonces; the token is never sent over the socket. The token has 128 random bits from `arc4random_buf`. Every JSON message includes version, PID, bundle, command, commandID, responseID, structured error and payload. Frame size is bounded to 4 MiB; old/malformed messages close the connection. Pending commands time out after 30 seconds, unpaired sockets after 10; no more than 16 connections. Length-prefix transport handles partial reads/writes. Heartbeats every 3 seconds maintain a 15-second inactivity bound. Agent disables interactive hooks on disconnect; only value patches with explicit per-app launch authorization may remain. No fixed jailbreak filesystem path, XPC/Mach entitlement or daemon service is used.

Protocol commands: `hello`, `helloChallenge`, `helloFinish`, `helloAck`, `heartbeat`, `ping`, `activate`, `deactivate`, `images`, `classes`, `methods`, `hookEnable`, `patchApply`, `patchPolicy`, `hookDisable`, `state`, `logs`, `static`. Agent rejects malformed command arguments and duplicate command IDs within a bounded 256-command window. UI rejects old protocol and structured errors. Authentication is not general network protection: token authorizes a local session and must be kept private; listener never binds an external interface. TCP messages after the handshake are not encrypted; a hostile jailbreak/root observer is outside this local opt-in threat model.

**Feasibility gate:** host transport tests do not establish real iOS sandbox behavior. Production incorporation is provisional until docs/device-validation.md confirms sandboxed fixture communication on each jailbreak. No claim of completed device gate is made. Controller finite background execution is sufficient only for short interactive switching; an always-running broker is intentionally deferred because entitlement/path feasibility must be demonstrated first.

## Hook choice and lifetime

Compared methods: ElleKit/Substrate hook registration can preserve original IMP but does not solve argument ABI capture; forwarding/NSInvocation needs interception of forwarding state and has forwarding/aggregate caveats; generic libffi needs audited ABI/platform integration. Selected `imp_implementationWithBlock` with one exact compiled wrapper per reviewed declaration. Runtime encoding is checked against the declaration, never used to generate arbitrary C casts. Fixture declarations remain fixture-bundle-only. Four SDK-reviewed exact system UIKit methods add support in other paired apps without claiming arbitrary nonvariadic signatures. Object echo wrapper is compiled MRC to preserve its reviewed +0 convention without ARC method-family inference.

Instance methods operate on the defining Class, class methods on its metaclass. Inherited Method entries are rejected to avoid changing superclass behavior. A recursive lock serializes engine changes and log/state access. Thread-local depth suppresses nested logger recursion while still delegating all calls. Original exceptions propagate via `@finally`, logging exception status. All supported calls invoke the immutable saved IMP with exact receiver/selector/arguments. Duration measures original call plus minimal timing overhead.

Disable compares current IMP to installed trampoline. If foreign, it disables logging and leaves it untouched. Runtime setImplementation return value detects a concurrent change and attempts conditional restoration. No public atomic CAS exists: an independently racing external writer cannot be completely synchronized by our lock. Do not claim atomic coordination with unrelated tweaks. Retired records/trampolines are never freed while calls/chains could reference them; 256-generation cap bounds retained resources. Engine lives for process lifetime.

## Static/runtime provenance and persistence

Agent can analyze its own bundle; Controller also analyzes installed bundle URLs when filesystem access permits, returning structured diagnostics on denial. Parser validates file-relative bounds, recursive type depth, fat slices, command sizes and strings. Encrypted/malformed files and unknown/future command IDs return structured errors; known uninterpreted commands remain numeric metadata. String pools and decoded arm64 class/metaclass method relationships are labeled partial `Static Only`; unresolved relationships are not inferred. Runtime records exclusively carry `Runtime Loaded`. UI keeps the catalogs separate, so identical names do not erase provenance. Future merged views must union records by path with separate sources and may never promote static entries based on names alone.

Per-bundle JSON stores identity, desired hook requests, observed hook state, last logs, up to eight analysis/history records and timestamps. Export schema includes provenance and partial/error fields. Controller settings do not silently auto-restore hooks; the separately authorized target-side launch policy may restore saved value patches. Each file has a 16 MiB serialization cap, evicting oldest history when necessary; malformed saved JSON is ignored. Filenames use SHA256 of bundle ID to avoid traversal/filename length problems. Write failure is reported to UI. Controller uses Foundation container/documents/temp URLs, with no jailbreak paths. Export tokens/credentials/proofs/nonces are never included. Static output has a 2 MiB global metadata budget, 128 KiB per image, and 128 MiB input-file limit; results indicate truncation/errors.

## Rootless and RootHide

Scheme-specific pinned Theos checkouts supply install prefixes, link/rpath handling and package architectures. Source does not open bootstrap paths: its data is in the app's Foundation locations, static inputs in target bundle, IPC in loopback. Therefore no artificial ROOT_PATH/jbroot conversion is necessary. Future bootstrap-resource paths must use Theos `ROOT_PATH(_NS)` for ordinary rootless and RootHide `jbroot()` API, never a cached random prefix. Mach-O is arm64 because only ordinary application processes are injected; package architecture is not CPU architecture.

## Application-first workflow and patches

Controller inventory is obtained through optional LaunchServices `defaultWorkspace` / `allInstalledApplications`; method signatures are checked with NSInvocation, errors are caught, and paired sessions remain usable when enumeration fails. Launch uses optional `openApplicationWithBundleID:` and accepts only observed void/BOOL return signatures. No fixed bootstrap path or unavailable private entitlement is used. Reference declarations: [Theos headers](https://github.com/theos/headers/blob/master/MobileCoreServices/LSApplicationWorkspace.h), [Procursus uiopen](https://github.com/ProcursusTeam/uikittools-ng/blob/main/uiopen.m). RootHide visibility must be validated on a device.

`patchApply` installs immutable scalar configuration under the engine lock. Exact compiled typed wrappers snapshot this configuration and replace the supported explicit argument before delegating to the original IMP. Only successful original returns may be overridden. Object/void/complex fields are rejected; scalar bounds and finite values are validated. The latest applied configuration is stored per bundle alongside the original reviewed method request. Hook disable and deactivation restore original behavior; disconnect does so for interactive hooks and for value patches without launch authorization. Applying values can change application semantics; no claim is made that every numeric value is meaningful to the application. Offline arbitrary-method creation remains incomplete. `patchPolicy` explicitly authorizes launch restoration (default off). Agent persists at most 128 reviewed method profiles/scalar patches in its host app's own NSUserDefaults under a unique namespace, without a shared filesystem path or stored token. Startup rechecks declarations, signature, identity and value bounds, rejects malformed/unsupported records, and reports restoreErrors. Only saved value patches survive disconnect when authorized. Hook disable removes its target-side saved entry; deactivate revokes launch authorization and disables all hooks. Controller retains a separate saved definition for explicit reapplication. No scanner runs merely because launch patch restoration is authorized.

Controller also calls the independent Static Analyzer directly on the installed bundle URL, on a utility queue. This needs no running process. File access failure is structured; target-side own-bundle analysis remains the fallback. Cached results remain Static Only, never promoted by filesystem enumeration.

Temporary logging allocations use a private autorelease pool after original delegation; original object returns remain under their caller's ownership conventions. Scalar patch snapshots have explicit MRC copy/release ownership. Parsed types are cached per record, and logged runtime object class names are limited to 256 bytes.

Controller rejects malformed command-specific response collections and pagination before using them. Persisted JSON is read with a capped NSFileHandle operation and known collections are sanitized before mutation/UI reuse. Static invalid UTF-8 fields are omitted with a structured error.

## App-first offline patch authoring (2026-10-04)

Installed app selection is the entry point; no PID is needed to browse its bundle or save a patch. The Static Analyzer associates arm64 `__objc_classlist` entries with class_ro names, instance method lists and metaclass method lists. `core/objc_metadata.inc` independently translates VM addresses through file-backed segments, supports 24-byte pointer methods and 12-byte relative methods, and walks declared dyld chains (PTR_64 / PTR_64_OFFSET) before decoding pointers. Only actual chain slots are decoded as fixups. Bound references, arm64e authenticated formats, multiple-start pages, categories and Swift-only metadata are not reconstructed; they produce partial structured diagnostics rather than guessed relationships. String pools remain separately available. File-only classes and methods always retain `Static Only`, even after their saved patch is applied.

ABI layout references: [Apple objc4 definitions](https://github.com/apple-oss-distributions/objc4/blob/main/runtime/objc-runtime-new.h) and [Apple dyld chain definitions](https://github.com/apple-oss-distributions/dyld/blob/main/include/mach-o/fixup-chains.h). No external parser or implementation is vendored. Decoder budgets are 128 segments/classlist sections, 20,000 classes/methods per list, 100,000 fixup slots, 16 KiB strings; existing per-image and per-bundle metadata budgets still apply.

Offline method details expose scalar patch creation only when a reviewed declaration matches the bundle/class/selector/encoding. The fixture's seven reviewed declarations can be authored offline; arbitrary application methods remain browse-only because encodings cannot prove a nonvariadic declaration. SDK UIKit profiles remain available through runtime analysis. This is intentionally a limited initial support matrix, not unrestricted Flex 3 compatibility.

Controller Store saves patch values plus the full method identity, encoding and provenance without requiring an Agent. Saved patches can be inspected and edited offline; connected sessions can apply or disable them. Agent verifies any supplied saved/static encoding against the currently loaded method before installing a hook, and persists that encoding in launch restoration profiles. A changed encoding returns `encoding_changed` without modifying an IMP. Shared scalar validation is used for both offline saving and Hook Engine application. Existing launch policy remains explicit: transfer patches to the Agent, then enable saved patches on launch. Authentication still protects IPC and is not a prerequisite for offline authoring.

## Foreground capture and return workflow

Installed-app selection writes a 90-second per-bundle launch capability. Agent reads only that custom type after activation, coalescing application/scene notifications and deferring synchronous paste access until activation callbacks return. Runtime scanner falls back to a full class-list/image association when image-local enumeration yields no classes. Capture runs on its serial background queue with 10 second / 8 MiB / 50,000-record budgets. It includes app-bundle images and a virtual Runtime Generated class group; live browsing remains available for system frameworks.

The earlier background-Controller socket/page/save workflow remains in code for interactive protocol compatibility but automatic analysis now uses the foreground result transport below. [Reference comparison and rationale](flex56-comparison.md). Partial results and zero Objective-C methods expose diagnostics; captured method details support offline patch saving. Immediate hook controls remain separate.

## Foreground capture result transport (0.2.3)

Automatic Analyze now captures locally in the selected Agent without connecting to the background Controller. The Agent creates a nested runtime snapshot, encodes a bounded 8 MiB JSON envelope with version/bundle/request/expiry and HMAC over the body, writes a dedicated result pasteboard type, and opens the Controller return URL. The foreground Controller verifies the current request, bundle, HMAC, expiry, catalog provenance/counts and size, then atomically persists and displays the result. It does not acquire a background transfer lease for this transport. Live hook controls retain their separately authenticated socket protocol. Custom pasteboard types are not an OS confidentiality boundary; no authentication key is included in the result or URL. Modern iOS may request ordinary paste permission on both sides; rejection does not erase previous saved results.

Controller deployment is signed with no-container/no-sandbox and container-required=false, matching a standalone jailbreak application whose Foundation Documents path may be outside a managed app container. The package inspector checks these exact three entries and rejects additional privileges on Agent/TestTarget. Target sandbox behavior and physical entitlement enforcement must be verified separately; this is not evidence that socket IPC works in a sandbox. The development-signed fixture still uses its normal provisioning profile and ordinary app entitlements.
